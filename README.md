# X5 Purchases MCP

Локальный MCP-сервер для изучения своих покупок в X5 Club через AI-агента. История загружается в SQLite; поиск и аналитика работают без обращений к X5. Подключение к агенту — через `stdio`, без открытого HTTP-порта.

**Статус: MVP проверен на живом API X5 2026-09-05.** Проверка подтвердила `200 text/x-script`, декодирование `turbo-stream`, нормализацию чеков и синхронизацию в локальную SQLite. Production fixtures не фиксируются в репозитории, чтобы не переносить персональные данные. Для нового аккаунта всё равно выполните probe и сверку с личным кабинетом: X5 может менять формат ответа без предупреждения. Подробности: [контракт и ограничения](docs/implementation.md).

## Установка

Нужны Node.js **24.x** и pnpm **10.33.0**. Скачайте этот репозиторий или переданный архив исходников и откройте терминал в его каталоге. Проект пока не опубликован в npm.

```sh
npm install -g pnpm@10.33.0
pnpm install --frozen-lockfile
pnpm build
```

Создайте `.env` из `.env.example`:

```powershell
# Windows PowerShell
Copy-Item .env.example .env
```

```sh
# macOS / Linux
cp .env.example .env
```

Эти команды нужны только при первой настройке: не перезаписывайте существующий `.env`.

Вставьте cookie локально:

```dotenv
X5_COOKIE="имя_cookie=значение; другое_имя=значение"
```

Чтобы получить значение, войдите в свой аккаунт на `https://x5club.ru`, откройте историю покупок и DevTools → Network. Поменяйте период или загрузите следующую страницу. В запросе `POST /lk/history.data` скопируйте **значение** заголовка `Cookie` из Request Headers, без префикса `Cookie:`. Не копируйте весь cURL, заголовок `Set-Cookie` или HAR. Не отправляйте cookie агенту или в чат.

Cookie даёт доступ к вашему аккаунту. `.env`, базы, HAR и логи исключены из git. Сервер не сохраняет cookie в SQLite и не выводит в ошибки. База содержит личную историю: не включайте `data/` и `.env` в архив для другого человека. Полученные через MCP данные становятся доступны выбранному агенту и его провайдеру; локальное хранение само по себе не делает модель локальной.

## Проверка и загрузка покупок

Сначала выберите небольшой период, в котором точно были покупки:

```sh
pnpm x5:probe --from 2026-08-10 --to 2026-08-15
```

Probe делает один запрос страницы `0`, проверяет декодирование и нормализацию. Выводит только HTTP status, тип и размер ответа, число чеков и результат проверки. Тело ответа и личные данные не печатает. Пустой ответ не доказывает, что API совместим: сверяйте число чеков с сайтом.

После успешной проверки:

```sh
pnpm x5:sync --from 2026-08-01 --to 2026-08-31
pnpm x5:recent
pnpm x5:search "кофе"
pnpm x5:status
```

Даты включительны. Период делится на календарные месяцы; страницы запрашиваются последовательно, начиная с `0`, до пустого массива. Между запросами есть задержка. Каждая страница сохраняется отдельной транзакцией. Повторный запуск обновляет чеки и заменяет их состав без дублей.

После первого завершённого импорта `pnpm x5:sync` берёт конец последнего успешного периода для тех же сетей минус 7 дней и загружает до сегодня. Это обновление последних данных, а не поиск старых пробелов: недостающие ранние периоды задавайте явно. Если связь оборвалась, повторите исходную команду с теми же датами. Уже сохранённые страницы останутся в базе; незавершённый период не помечается полным. Длительный первоначальный импорт удобнее выполнять через CLI.

## Подключение к агенту

Агент должен запускать **`node` напрямую**, без `pnpm start`: менеджер пакетов может печатать служебный текст в stdout. В stdout сервера идут только сообщения MCP. Приложение агента самостоятельно запускает и останавливает сервер.

Конфигурация `.env` по умолчанию ищется в каталоге проекта, независимо от рабочей папки агента. Для другого расположения задайте `X5_ENV_FILE` абсолютным путём. Относительный `X5_DB_PATH` разрешается относительно этого `.env`. Переменные окружения процесса имеют приоритет над файлом.

### Codex

Добавьте блок из [examples/codex.toml](examples/codex.toml) в свою конфигурацию, заменив пути:

```toml
[mcp_servers.x5]
command = "node"
args = ["C:/path/to/x5-mcp/dist/index.js"]
startup_timeout_sec = 20
tool_timeout_sec = 300

[mcp_servers.x5.env]
X5_ENV_FILE = "C:/path/to/x5-mcp/.env"
```

На macOS/Linux используйте пути вида `/Users/me/x5-mcp/dist/index.js`. Если приложение не находит Node, укажите абсолютный путь к `node`/`node.exe` в `command`. Формат `mcp_servers`, запуск stdio и таймауты сверены с [официальной документацией Codex](https://developers.openai.com/codex/mcp/). Перезапустите подключение MCP после изменения cookie или сборки.

### Другие MCP-клиенты

Для клиентов с конфигурацией `mcpServers` используйте [examples/mcp.json](examples/mcp.json):

```json
{
  "mcpServers": {
    "x5": {
      "command": "node",
      "args": ["C:/path/to/x5-mcp/dist/index.js"],
      "env": { "X5_ENV_FILE": "C:/path/to/x5-mcp/.env" }
    }
  }
}
```

Расположение файла конфигурации зависит от вашего клиента. Этот проект предоставляет локальный stdio transport; клиенту с обязательным удалённым HTTP-сервером нужен отдельный адаптер, который в MVP не входит.

Для аналитики без сетевой синхронизации из агента задайте `X5_ENABLE_SYNC_TOOL=0`. Это скрывает инструмент синхронизации; CLI sync остаётся доступен. Несколько агентов могут читать одну базу, но синхронизации одной базы выполняются по очереди. Для другого аккаунта используйте отдельные `.env` и `X5_DB_PATH`: автоматического распознавания смены аккаунта нет.

## Инструменты и сценарии

| Tool | Назначение |
|---|---|
| `x5_sync_history` | Загрузить/обновить заданный период |
| `x5_get_sync_status` | Проверить покрытие и свежесть истории |
| `x5_get_recent_receipts` | Последние чеки, `limit`/`offset` |
| `x5_get_receipt` | Чек по ID и его состав |
| `x5_get_spending` | Итоги чеков за период, по дням/неделям/месяцам |
| `x5_search_purchases` | Поиск названия, фильтры периода/сети/категории |
| `x5_get_product_history` | История покупок и цен конкретного PLU |
| `x5_get_top_products` | Частые товары по числу чеков |
| `x5_get_categories` | Исходные коды категорий |
| `x5_get_category_spending` | Предварительная оценка трат по категориям |
| `x5_get_price_changes` | Первая и последняя цена PLU за период |

Примеры запросов агенту:

- «Проверь полноту истории за август 2026 и покажи расходы по неделям».
- «Найди мой кофе и покажи последние покупки и изменение цены».
- «Какие 20 товаров я чаще всего покупал за полгода?»
- «Какие регулярно покупаемые товары подорожали? Отдели возможные акции».
- «Покажи категории покупок за август и предварительные оценки расходов».

Готовые инструкции для агента: [docs/scenarios.md](docs/scenarios.md). Сервер также предоставляет MCP prompts `x5_monthly_review`, `x5_product_review`, `x5_shopping_patterns`, `x5_savings_review` с аргументом `request`. Клиенты без поддержки prompts могут использовать обычные сообщения из документа.

Все денежные поля `*_minor` — целые копейки RUB. `null` — неизвестно, не ноль. Расходы считаются по `amountPromo` чека и не суммируются повторно для каждой позиции. Категорийные суммы **оценочные**: `pricePromo × quantity`, округление каждой позиции. Семантика товарных цен требует сверки с личным кабинетом на ваших данных, поэтому такие суммы не заменяют итоги чеков. В живом ответе, проверенном 2026-09-05, код сети на уровне чека не пришёл в ожидаемом поле `codeTc`, поэтому `networkCode` может быть `null`; названия категорий и соответствия кодов сетей не выдумываются.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `X5_COOKIE` | пусто | Нужна только для сетевых запросов |
| `X5_ENV_FILE` | `.env` в проекте | Абсолютный путь; задаётся окружением агента |
| `X5_DB_PATH` | `data/x5.sqlite` | База, отдельно для каждого аккаунта |
| `X5_NETWORK_CODES` | `D,S,VK,SL,VP` | Исходные коды сетей через запятую |
| `X5_REQUEST_TIMEOUT_MS` | `30000` | Таймаут одного запроса, 1000–120000 мс |
| `X5_PAGE_DELAY_MS` | `500` | Пауза между страницами, 100–10000 мс |
| `X5_MAX_PAGES_PER_MONTH` | `1000` | Защита от бесконечной пагинации |
| `X5_SYNC_FROM` | пусто | Начало первого импорта без `--from` |
| `X5_ENABLE_SYNC_TOOL` | `1` | `0` скрывает сетевой MCP tool |

## Ошибки

- `X5_AUTH`: обновите browser session и `X5_COOKIE`, перезапустите сервер. Также возможна блокировка сайта: автоматического обхода нет.
- `X5_RATE_LIMIT`: подождите и повторите исходный период; автоматического агрессивного retry нет.
- `X5_REQUEST`: ошибка связи/HTTP/таймаут/слишком большой ответ. Повторите позже.
- `X5_DECODE` / `X5_UNEXPECTED_RESPONSE`: формат ответа не поддерживается. Нужна проверка обезличенного ответа; не отправляйте HAR с секретами.
- `X5_NORMALIZE`: чек не соответствует контракту ADR. Страница целиком отклонена, чтобы не записывать неверные суммы или удалять состав старого чека.
- `X5_RANGE` / `X5_PAGINATION`: X5 вернул другой период или повторяет страницы. Импорт не помечается полным.
- `SYNC_BUSY`: другой процесс синхронизирует эту базу. После аварийного завершения блокировка истечёт примерно через 2–4 минуты.
- Ошибка сборки `better-sqlite3`: проверьте Node 24 и выполните `pnpm install --frozen-lockfile` под этой версией. На платформах без готового бинарника понадобятся инструменты сборки `node-gyp`.
